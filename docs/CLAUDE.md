## What this project is

TradingOS is an AI multi-agent trading operating system for Indian equity & F&O markets (NSE/BSE). A 24-agent LLM organization, led by a CEO Agent, autonomously researches markets, generates and validates trading strategies, backtests them, and runs them in paper trading — all fully autonomous. **Live capital runs autonomously too, once a strategy is live-eligible and its own master switch is explicitly on — real money is never moved without a human decision, but that decision is a per-strategy autonomy switch, not a per-order approval; from there, only the deterministic safety layer can stop an order (see Non-Negotiable Rule #1).** This is a solo-operator project, self-hosted, not multi-tenant, not built for public/enterprise scale.

## Non-negotiable rules — never violate these regardless of what a feature request seems to imply

1. **Live-money orders execute autonomously — the deterministic safety layer is the only thing that can stop one, never a human clicking Approve.** (Phase 18 redesign; see Build Spec §12 for the full mechanics and history.) A strategy earns live eligibility exactly once, through the Go-Live Readiness Gate (Build Spec §7). Autonomous execution additionally requires a separate, explicitly-confirmed **"Live Autonomous Trading" master switch** per strategy (`LiveTradingSubscription.autonomous_trading_enabled`), defaulting OFF for every strategy including already-live-eligible ones, flippable only through `set_autonomous_trading` with a real actor and its own audit-log entry, and checked first — before even the Kill Switch — inside `generate_live_order_intent`. Once both the readiness gate and the master switch are on, every triggering tick resolves synchronously with no per-order human approval step and no multi-second decision window. The only things that can prevent an order from reaching the broker from that point on are: the master switch itself, the **Kill Switch**, the **standing per-strategy rate/notional caps** (`max_intents_per_window`, `max_notional_per_intent` — mandatory and always-on, never optional), the **Compliance Checker**, the **Correlation Constraint**, and the **Naked-Options Scanner** — all deterministic Python, never LLM-judged, checked in the same fixed order every time. No exceptions, no bypass path: no code path exists where an agent or scheduled job submits a live order around any of these checks, and no orchestration change may create one.
2. **The safety layer sits above the agents, never inside them.** Kill Switch, Compliance Checker, Naked-Options Scanner, Correlation Constraint, and the Go-Live Gate are deterministic Python, not LLM-judged, and no orchestration change may create a path around them.
3. **Heartbeat and any proactive/background agent behavior is read-only.** It may raise alerts and open tasks; it must have no reference to order-placement or risk-limit-mutation functions in its execution context — not just a permission check, an actual absence of the capability.
4. **No MFA.** Auth is password + JWT (15-min access / 7-day rotating refresh) + RBAC only. Don't add TOTP/MFA scaffolding even if a library makes it convenient.
5. **Skills are internal-only.** No dynamic loading of unreviewed/third-party code as an agent "skill." Every skill ships in this repo and is reviewed like any other code change.
6. **Strategy code execution is sandboxed.** LLM-generated strategy code never runs with raw filesystem/network/shell access outside the sandbox boundary (Build Spec §9).
7. **Every mutation is audited.** Any state-changing action — including Agent Gateway config changes — writes an append-only audit-log row. If you add a new mutating endpoint, add its audit entry in the same PR/commit, not later.
8. **Migrations are additive.** Never write a destructive schema change into `upgrade()`; it belongs in `downgrade()` only.

## Working conventions

- Type hints everywhere; Pydantic models for all API request/response shapes and the Agent Gateway config schema.
- `pytest` for backend tests; a risk-critical module (Kill Switch, live-intent expiry, Compliance Checker) is not done until it has unit tests AND is on the mutation-testing list.
- Alembic for every schema change — no manual SQL against the dev DB.
- `ruff` + `black` (or `ruff format`) — run before considering a phase complete.
- Structured logging via `structlog` with a correlation ID threaded from HTTP request → orchestration run → agent action → order.
- When a phase's prompt (in the Build Prompt Pack) says to write tests for a specific behavior, write them — don't defer "we'll add tests later."
- If you find a spec ambiguity or something in the Build Specification that doesn't quite fit once you're actually writing code, stop and ask rather than silently deciding — flag it plainly (this is a solo project; there's no one else reviewing the diff).

## Development & Testing Workflow

- Development happens wherever the active session runs today — that doesn't change.
- Nothing counts as done until it's been tested against the real local Docker stack: after a phase's work is committed and merged to the main branch, pull the latest merged code onto `D:\TradingOS-2.0\TradingOS-2.0` (`git fetch && git pull`), then bring the stack up fresh (`docker compose down && docker compose up --build`, or `pnpm docker:up` / `scripts/docker-up.cmd` per the Phase 1 notes below) and re-run that phase's acceptance criteria there — not wherever the code was originally written.
- Real credentials (broker OAuth, LLM provider keys, notification channels) only get exercised during this local pass at `D:\TradingOS-2.0\TradingOS-2.0`. Never commit real secrets — supply them through the Settings UI or a local, gitignored `.env` on this machine only.
- **First-time setup on `D:\TradingOS-2.0\TradingOS-2.0`:** copy `.env.example` to `.env` and set `SECRETS_ENCRYPTION_KEY` (`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`) before testing anything in the Settings UI — Broker Config, LLM Providers, and Notification Channels all share this one encrypted store and 503 without it (the backend logs a non-fatal startup warning naming this if it's left unset; everything else, including paper trading, works fine without it). If configuring a local/custom LLM provider (Ollama, LM Studio, etc.), use `http://host.docker.internal:11434` as the base URL, not `http://localhost:11434` — `localhost` inside the backend container refers to the container itself, not the host machine running Ollama.
- A phase is not complete until it has passed this pull-and-test cycle at `D:\TradingOS-2.0\TradingOS-2.0`, in addition to whatever automated tests ran during development.
